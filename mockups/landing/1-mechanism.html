Four steps, no discretion for the model to expand its own reach.

Each stage is a bounded Spring service with a typed input and output — not an agent with open-ended tools.

01 / INTAKE

An analyst submits an order ID

Nothing else is uploaded. No CSV exports, no pasted order data — just the identifier the analyst already has.

02 / CONNECTOR

One query reads dispute_case_view

A code-owned, parameterized statement — the same one every time, on a read-only database identity.

03 / RETRIEVAL

Policy filtered to the order date

Effective-date and document-type filters run before vector search, in the merchant's own time zone.

04 / APPROVAL

A human signs off before export

The draft is advisory until an analyst approves an exact revision. The hash is recorded, not assumed.
